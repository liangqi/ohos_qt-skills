## semantic

- [qdrag-cancel-cross-platform](../semantic/qdrag-cancel-cross-platform.md) — The state of cross-platform support for programmatic drag cancellation via QDrag::cancel(): Windows and X11 implement it (an OLE flag / the QBasicDrag event loop), while macOS (Cocoa) and OHOS do not (cancelDrag falls through to a Q_UNIMPLEMENTED no-op). On OHOS, calling it doesn't crash or hang but silently does nothing, and exec returns once the native drag ends naturally. Includes a demo extending the official draggableicons example and a file:line evidence chain for each platform.
- [qt-harmonyos-accessibility](../semantic/qt-harmonyos-accessibility.md) — The Qt OHOS accessibility (a11y) bridge and how to enable it: libqohos contains QOhosPlatformAccessibility (a QPlatformAccessibility subclass) that publishes Qt's QAccessible widget tree to the OHOS accessibility framework through each QWindow's XComponent native ArkUI_AccessibilityProvider (via callbacks such as findAccessibilityNodeInfosById). The bridge is off by default and is enabled by the [boolean launch Want parameter io.qt.experimental.enableA11ySupport] (aa start --pb io.qt.experimental.enableA11ySupport true) — not by an env variable, not by an appArg, and not automatically by a system screen reader. Once enabled, uitest dumpLayout -b <bundle> returns the complete Qt widget tree (QApplication/QWidget/QPushButton/QLabel + text + bounds); the DevEco MCP get_app_ui_tree goes through the ArkUI inspector and only reaches the XComponent node (no Qt widgets).

Each category has a mapping table and code examples.
- [qt-harmonyos-api](../semantic/qt-harmonyos-api.md) — Key Qt API compatibility points for HarmonyOS porting: argv differences, choosing a child-process approach per scenario (headless can use QProcess / a Qt UI uses startAppProcess / a non-Qt UI uses startAbility), window model differences (QDialog/Popup are subwindows), modality only applying to subwindows, winId() not being a native handle, the public path to an OHNativeWindow* via setSurfaceConsumer, hide() having different semantics, setMask() only working on subwindows, and closeEvent possibly coming from the system lifecycle. Platform detection: Qt.platform.os returns "linux" on HarmonyOS (upstream's os() has no Q_OS_OHOS branch) — use pluginName for now, and an upstream fix is recommended. Device type detection: Qt exposes no public device-type interface; QtCore's private QOhosDeviceInfo (Q_CORE_EXPORT, includable and linkable, but with only three tiers — 2in1/tablet/phone — and essentially a cache of @ohos.deviceInfo) is usable, though applications are better off calling @ohos.deviceInfo directly through Node-API.
