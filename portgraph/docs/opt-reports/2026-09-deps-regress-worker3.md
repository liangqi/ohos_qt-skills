## 6. Residual items (not fixed this round, recorded)

1. **keyutils (corpus-c)**: inside an `if("${CMAKE_SYSTEM}" MATCHES "Linux")`
   block — LINUX is treated as active on OHOS and not downgraded (conservatively required). The verdict is reasonable: OHOS musl has no
   keyutils.h, so porting genuinely needs attention; the tool can't statically determine the value of CMAKE_SYSTEM
   under the OHOS toolchain.
2. **corpus-a's 2 missed-deps**: pre-existing in the baseline (drift between the upstream README and build files);
   see the residual items in `docs/opt-reports/2026-09-deps-test-worker1.md`.
3. **Discount is required=True after merging**: merging pkg_check_modules (required semantics) and
   find_package (no REQUIRED) for the same library yields required (the conservative direction, per _DepBook's existing
   merge rules); on the gen-b side set_package_properties actually marks it optional — being fully precise
   would need call-site context inside the Find module, with low payoff.
4. **The whole KF6 family is need_port** (gen-b 24 / gen-c 26 items): a data-source gap; the real fix
   is to submit the KF6 formula set to Harmonybrew.
5. **Platform inheritance from a find_package inside a platform block into the contents of the Find<Name>.cmake module** is not implemented
   (conservatively treated as required).
6. **The submodule state of the corpus-b clone** affects comparability (§5); recommend that the e2e harness
   warn on clones with uninitialized submodules.
